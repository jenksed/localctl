# LocalCTL v0.3 — Find the Edges

v0.3 turns LocalCTL from a growing scenario runner into an experiment workbench whose evidence is deliberately shaped for later capability intelligence.

## Release question

> What can this exact local model, artifact, profile, runtime, and machine actually demonstrate?

v0.3 does not answer whether a model is universally good, qualified for autonomous work, or authorized to take action.

## Learner path

```text
localctl lab
    ↓
localctl models
    ↓
localctl audition <model>
    ↓
localctl verify ...
    ↓
localctl report <model>
    ↓
localctl gaps <model>
```

For a controlled two-model experiment:

```text
localctl headtohead <model-a> <model-b>
```

## Evidence hierarchy

```text
machine/runtime observation
        ↓
deterministic evaluator
        ↓
human judgment where needed
        ↓
later derived capability state
        ↓
later AI analysis
```

AI interpretation is intentionally absent from v0.3's evidence derivation path.

## Schema v3

New observations carry enough provenance to support future comparison and analysis without rewriting older evidence:

- run, session, and experiment identity;
- exercise and pack version;
- canonical/private input class;
- prompt and response digests;
- machine OS/architecture and observable hardware facts;
- LocalCTL version/build identity when embedded by Go;
- GGUF content SHA-256 and filename-derived quantization;
- llama-server process/executable/version identity where observable;
- profile and requested/observed context;
- token/timing telemetry exposed by llama.cpp;
- point-in-time runtime RSS when available;
- validation authority and evaluation result.

Older v1/v2 evidence remains readable and is not upgraded by inference.

## Experiments and sessions

A run is one observation.

An experiment groups runs that were intentionally executed under one model/profile/workload definition.

A session groups related experiments, such as the two sides of a head-to-head comparison.

This means future intelligence can distinguish:

```text
historically related
```

from:

```text
comparable by experiment design
```

## Profiles

Built-in profiles currently expose a small, understandable configuration surface:

```text
default       ctx=2048  temp=0  max=512
fast          ctx=2048  temp=0  max=256
long-context  ctx=8192  temp=0  max=1024
```

A profile change restarts the managed runtime when necessary. LocalCTL does not silently reuse a runtime under a different requested profile.

## Versioned packs

Canonical workloads are grouped into versioned manifests:

```text
core-baseline/v1
developer-core/v1
linux-investigation/v1
docker-investigation/v1
kubernetes-investigation/v1
writing-summarization/v1
structured-output/v1
reasoning-analysis/v1
```

A future prompt/scoring change that materially changes a pack should produce a new pack or exercise version rather than silently altering historical meaning.

## Adaptive audition

`localctl audition` begins with the core baseline, then samples useful capability categories. A clean early signal stops the category sample early; mixed or weak evidence causes additional discriminator exercises to run.

The adaptive rule is deterministic. No LLM chooses which tests make itself look better.

## Repeatability

`localctl verify` repeats deterministic tasks and reports:

```text
STABLE_PASS
USUALLY_PASS
FLAKY
USUALLY_FAIL
STABLE_FAIL
UNKNOWN
```

Three identical deterministic outcomes are enough for early stopping in v0.3. These labels are experiment summaries, not universal qualification states.

## Private real work

`localctl work` allows bounded user-supplied material such as diffs and logs to become historical observations while remaining explicitly separate from canonical benchmark evidence.

Private work is never silently reclassified as canonical.

## Resource evidence

v0.3 records runtime startup duration when a runtime is started and a point-in-time process RSS sample on new observations when the OS exposes it.

Process RSS is not peak memory and is not complete Apple Metal/unified-memory accounting. LocalCTL preserves that limitation rather than manufacturing a more impressive number.

## Deterministic validation boundary

Current machine evaluators include exact string contracts, required-concept checks, and semantic JSON equality.

Generated programs are not executed on the developer host as part of v0.3. Compiler/test-based evaluation remains a candidate for a later isolated validator boundary.

## v0.4 seam

v0.4 may derive capability intelligence from v0.3 artifacts:

```text
Observation v3
Experiment
Session
Profile
Pack/version
Failure kind
Human judgment
Resource evidence
```

Likely v0.4 concepts include evidence strength, freshness, capability state, model roles, requalification, and workload recommendations.

Those thresholds are intentionally not frozen in v0.3. Dogfood evidence should inform them.

## v0.5 seam

v0.5 may allow local models to analyze bounded evidence, but AI output must be a separate artifact with provenance:

```text
analyst model/profile
compiled source evidence IDs
analysis/claims
hypotheses
proposals
human judgment
```

The future invariant remains:

```text
AI analysis != observation
AI hypothesis != fact
AI proposal != authority
```

v0.3's job is to make that future analyst safe to build by giving it structured, inspectable evidence instead of a pile of ambiguous transcripts.
