# LocalCTL v0.3 learner UX review

This review treats the v0.3 evidence/runtime behavior as the product foundation and asks a narrower question:

> Where does the CLI make the learner decide too much before LocalCTL has helped them understand what matters?

The goal is not to hide evidence. The goal is to make default surfaces answer one operator question at a time.

## UX rule

```text
default output = answer the current operator question

help/detail output = expose the wider capability surface

experiment output = preserve the evidence trail
```

That distinction matters. A quiet command directory is good UX. A quiet experiment transcript can be bad evidence UX.

## Surface review

| Surface | v0.3 problem | Decision |
| --- | --- | --- |
| bare `localctl` | returned only a terse usage error | show learner-oriented help and exit successfully |
| `localctl lab` | behaved like a directory of equally weighted commands | show state plus one deterministic next step; move the command catalog to `help` |
| `localctl models` | included hard-coded Granite/Ministral/Ornith examples unrelated to the current machine | show installed models, active marker, and historical run count; use actual IDs in guidance |
| `localctl explore` | mixed curated recommendations, long rationale, URLs, machine assumptions, and live discovery | make it a compact discovery inbox |
| `localctl explore --live` | up to 15 repository rows plus a URL row for each result | show 5 by default; `--all` opts into 15; remove duplicate URL lines |
| candidate lifecycle | already-installed models remained visible in discovery; there was no shortlist | hide installed models, persist a selected-for-audit queue, auto-prune a selection once the GGUF is installed |
| `audition` | verbose | keep detailed: it is an experiment transcript, not navigation output |
| `verify` | verbose | keep detailed: trial-by-trial visibility is the property being measured |
| `headtohead` | verbose | keep detailed: both sides need visible controlled evidence before the summary |
| `missions` | concise question-first entry point | keep |
| `packs` | taxonomy-heavy | keep as an explicit advanced/inspection surface; do not promote it above missions/audition |
| `work` | clear private-input boundary and explicit human judgment | keep |
| `report` | dense but bounded historical evidence | keep; v0.4 owns derived capability interpretation |
| `gaps` | gives a useful deterministic next experiment | keep and use it as the lab next step once a model already has evidence |
| `runs` / `show` / `judge` | evidence workbench | keep; expose under “Read the evidence” rather than the initial path |
| `runtime` / `evidence audit` | machine-truth glass box | keep; expose under advanced/glass-box help rather than as a first-run menu |
| `baseline`, `suite`, `compare`, `insights`, `experiment`, `try` | useful compatibility/power surfaces but too many nouns for a new learner | retain behavior, de-emphasize in primary help |

## Explore lifecycle

The revised exploration surface has three states:

```text
DISCOVERY INBOX
  candidate is not installed and not selected
        |
        | localctl explore select <candidate>
        v
AUDIT QUEUE
  candidate is intentionally worth investigating
        |
        | install GGUF with preferred model manager
        v
INSTALLED MODEL
  LocalCTL discovers it under ~/.lmstudio/models
  candidate automatically leaves explore
        |
        v
localctl models
localctl audition <model>
```

Selection is not qualification. It records operator intent only.

The queue is stored at:

```text
~/.localctl/explore.json
```

This file is learner state, not run evidence. It does not alter observations under `~/.localctl/runs`.

## Command shape after the cleanup

### Front door

```bash
localctl
localctl lab
localctl models
localctl audition <model>
```

### Discovery

```bash
localctl explore
localctl explore select <candidate>
localctl explore audit
localctl explore unselect <candidate>
localctl explore --live
localctl explore --live --all
```

### Controlled learning

```bash
localctl headtohead <a> <b>
localctl verify <exercise> <model>
localctl missions
```

### Evidence

```bash
localctl report <model>
localctl gaps <model>
localctl runs
localctl show <run-id>
localctl judge <run-id> ...
```

### Detail / glass box

```bash
localctl help
localctl packs
localctl profiles
localctl exercises --all
localctl runtime ...
localctl evidence audit
```

## What this patch intentionally does not do

It does not add an automatic model downloader. LocalCTL should not convert “interesting candidate” into “mutate my machine” without a separate authority design.

It does not make Hugging Face recency or download count into a quality score.

It does not remove experiment IDs, run IDs, failure kinds, or trial-level output from experiment commands merely to make screenshots shorter.

It does not turn the v0.3 `report` into v0.4-style capability policy. v0.3 still records and characterizes evidence; v0.4 derives bounded intelligence from comparable evidence.

It does not delete compatibility commands simply because they are no longer promoted in the primary help path.

## Forward-port contract

v0.4 should inherit these UX rules:

1. installed models never remain model-discovery candidates;
2. selection for audit remains operator intent, not model qualification;
3. `lab` gives one next action before showing taxonomy;
4. primary help is layered by user intent rather than implementation module;
5. experiment transcripts remain inspectable;
6. capability intelligence can add decision support, but should not reintroduce a flat wall of commands.
